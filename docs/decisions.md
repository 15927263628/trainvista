# 决策与讨论

状态：讨论稿 v0.2。用户已确认实验性质、公开工具由助手选择、Leader 首屏由助手筛选，并纳入重跑、终止和审批。具体实现尚未启动。

## 1. 推荐基线

| 主题 | 推荐 | 原因 |
| --- | --- | --- |
| 名称 | TrainVista，仓库 `trainvista` | 表达训练全景，暂未做商标或全网重名核查 |
| 可见性 | 私有 | 在内部流程、数据边界和开源策略未确认前限制披露 |
| 产品定位 | 观察、追踪及受控操作层 | 不自建执行引擎，操作委托 Prefect |
| 核心模型 | DAG + 阶段尝试 + 版本化产物 + 指标定义 | 覆盖控制流、数据流和异构展示 |
| 首批用户 | Leader 总览与工程师下钻共用同一数据模型 | 避免管理看板与实际任务各说各话 |
| 指标设计 | 固定通用语义 + 组件声明扩展 | 各工具可独立扩展，不重写核心页面 |
| 接入方式 | 有事件用事件，否则增量轮询；自定义脚本支持 HTTP | 兼顾更新速度和接入成本 |
| 架构 | 模块化单体 + worker + 远程 PostgreSQL | 控制早期运维成本，保留演进路径 |
| 首次接入 | AG News 小模型实验、Prefect 与 MLflow | 验证从数据快照到审批交付的完整关联 |
| 数据策略 | 摘要与引用集中，权重及高频曲线留在来源 | 避免重复建设与存储膨胀 |

## 2. 首轮结论

### A. 实验流水线与工具

无需用户提供内部工具。选择 Hugging Face Datasets、Transformers/PyTorch、scikit-learn、Prefect 与 MLflow；用小样本 AG News 四分类覆盖数据准备、训练、评测、审批及交付，详见[实验设计](experiment.md)。

### B. Leader 首屏

推荐兼顾 Leader 看总体进展和工程师定位阶段，默认 30 至 60 秒更新即可。若要实时诊断训练性能，应优先连接现有高频监控而非全量复制。

已筛选三类信息：待介入风险、候选交付就绪度、阶段进展与阻塞。数据新鲜度常驻；历史成功率、loss 和吞吐曲线降为次级视图，不显示缺乏依据的交付时间预测。

### C. 是否需要操作已有流水线？

用户已要求重跑、终止和审批。首版重跑支持整条及训练/评测检查点，终止仅支持整条运行，审批绑定不可变证据并禁止自批。新增操作记录、事务 Outbox、权限、并发校验及外部结果对账，不扩展到拖拽编排。

## 3. 实施前补充确认

- 接入条件：实验脚本主动传递统一 ID；真实执行需提供远程 Prefect / MLflow 地址和最小权限服务身份。
- 部署：推荐应用可本机运行，但 PostgreSQL、Prefect/MLflow 后端及对象存储均使用远程环境；地址和授权仍待提供。
- 规模：每日运行次数、同时活跃节点数、最大 DAG、曲线采样频率与保留时间。
- 权限：公司 SSO、项目隔离、跨团队共享、产物下载和样本脱敏要求。
- 团队：是否有既定前后端框架，以及维护 Python 连接器的人员。
- 仓库：已核验 owner 并创建 `15927263628/trainvista`，私有，无许可证，公开前另行审核。

## 5. 主要风险

| 风险 | 早期验证 / 应对 |
| --- | --- |
| 各工具无法串联同一次训练 | 先做 ID 贯通验证；不能映射的记录明确标为待关联 |
| 同名指标含义不同 | 定义单位、对象、窗口、维度与版本，不自动做跨口径平均 |
| 重试与产物复用造成错误血缘 | 显式 Attempt 和不可变版本绑定，保留消费事实 |
| 总览把过期数据当作实时状态 | 同屏展示来源及最后更新时间，采集健康单列 |
| 构建成另一套庞大的训练平台 | 仅包装预定义调度器操作，不承担执行引擎、托管与日志存储 |
| 存储量远超预期 | 试点先测指标点数、降采样效果和保留成本 |
| 外链绕过平台权限 | 平台和原存储双重授权，不持久化公开或长期签名下载链接 |
| 命令超时导致重复训练或登记 | 幂等键、事务 Outbox、外部 ID 对账，结果不明时暂停重发 |
| 审批与终止竞态 | 锁定证据、修订号检查、运行级锁、交付前复核及外部补偿 |
